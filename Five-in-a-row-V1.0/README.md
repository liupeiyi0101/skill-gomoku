# 技能 五子棋

响应式网页五子棋，支持标准 Swap2、Hero001 技能娱乐模式、同机双人和局域网 1v1。第一个英雄「小果」已接入，采用你确认的白粉帽兜 Q 版人物图。原始 `main.txt` 和 `heros.xls` 保持不变。

## 当前美术方向

**未来潮玩 × Q版科技**：深靛蓝背景、浅紫色圆角竞技台、白粉角色与蛛丝特效。双方默认选用唯一已开放英雄「小果」。专属蛛网棋子使用珊瑚红圆形与冰蓝六边形，通过颜色和轮廓双重区分。同英雄对战不会混淆所属阵营。

## Hero001 · 小果

- 原图作为准备室卡面和头像；玩家 A 位于棋盘左下、玩家 B 位于右上，不随 Swap2 选边交换站位。
- 两个方向分别有待机、蓄力、发射、牵引四张动作关键帧。落子使用「蓄力 → 发射蛛丝 → 落点凝结 → 收手」，约 0.76 秒；技能换位约 1.25 秒。
- 顶部切换标准 / 娱乐模式。同机已有棋局时切换需要确认；联机房间在创建时确定模式，重连和再来一局保留模式。
- **标准模式**：只有角色、专属棋子和落子动画。服务端同样拒绝技能，天赋不触发。
- **娱乐模式试玩细则**：完成选边后，每个自己的回合可在正常落子前使用一次「蛛丝换位」，移动任意一方的一颗棋子至空交叉点，随后仍可落子。点击「使用技能」→ 选棋子 → 选空位 → 确认换位；可随时取消选择。换位后检查全盘恰好五连，胜利归棋子所属方，包括移走长连端点后露出的五连。
- **蜘蛛感应**：仅娱乐模式正常落子后，如果该棋子在任意方向形成至少三颗连续同色棋子，另一位玩家的小果身旁出现「!」。开局摆子与技能换位不触发。
- 使用次数、空位目标、三连及以上等边界是本次第一版试玩解释，不是表格明写的全部规则；集中记录在 [Hero001 实装说明](web/docs/heroes/hero001.md)，可继续调整。
- 动作素材目前是有浅色格纹底的关键帧图，在角色展示框内播放；不是透明抠图、连续骨骼动画或真正的 3D 模型。两个视角的兜帽状态略有差异。定稿原图保持原样。

- 预选落点有瞄准提示；确认后棋子弹跳入场并扩散短暂能量波纹；五连获胜时高亮连线。
- 系统开启“减少动态效果”时，界面会停用动画与过渡。
- **珊瑚红 = 原规则黑方（1），冰蓝 = 原规则白方（2）**。开局顺序为红、蓝、红；补摆为蓝、红；选边后仍由冰蓝方先下。只是更换皮肤，不改变 Swap2 规则。
- 皮肤配置与渲染独立在 `web/lib/presentation.ts`、`web/components/energy-token.tsx`，不改变存档格式或联机协议。后续角色皮肤可沿这个边界加入。

## 开始玩

在当前电脑上双击 **启动游戏.cmd**。看到“弈间已启动”后，在浏览器打开 **http://localhost:4173/**。游玩时保留启动窗口，关闭窗口或按 Ctrl+C 即停止服务。如果提示端口占用，通常是游戏已启动，直接打开网页即可。

- **同机双人**：两人共用一个屏幕，根据提示轮流操作。点击棋盘交叉点预选，再点“确认落子”；可以关闭落子确认。
- **局域网联机**：两台设备连接同一 Wi-Fi。主机在网页切换“局域网联机”并创建房间。将邀请链接发给朋友，或让朋友打开页面显示的局域网地址并输入六位房间号。无需注册账号。
- 朋友必须打开主机的 `192.168.x.x` 等局域网地址，不能在自己的设备上打开 `localhost`。
- 手机只能作为浏览器客户端，本版需要一台运行服务的电脑。两台手机之间不直接充当服务器。
- 若手机无法访问，检查 Windows 防火墙是否允许 Node 在**专用网络**通信；不要关闭整个防火墙。访客 Wi-Fi 或开启客户端隔离的路由器也可能阻止互相访问。

## 标准模式固定规则

1. 15×15 棋盘，棋子放在空交叉点上；无吃子、移动和悔棋。
2. 开局方依次摆黑、白、黑三子，落点不限。
3. 另一方可以选择执黑、选择执白，或补摆一白一黑两子。
4. 如果补摆两子，由最初开局方最终选择颜色，不能继续补子。
5. 选色后由白方落下一手，之后黑白轮流，一手一子。
6. 双方都必须**恰好五连**才获胜。六连或更多长连合法但不获胜；同时在另一个方向形成恰好五连仍获胜。
7. 双方均无三三、四四禁手。棋盘下满无人获胜则和棋。可以在正常对弈阶段认输。
8. 第一版不限时；联机再来一局需双方同意，新一局交换开局方。

参考：[RIF Swap2 开局](https://www.renju.net/rule/11/)、[竞技 Gomoku 规则说明](https://www.vcpr.cz/en/help-and-rules/gomoku-rules/)。界面在选边前使用玩家 A / B 身份，而不是预先把某个玩家固定为黑方。

## 保存和联机边界

- 同机对局通过操作记录保存在当前浏览器本地，刷新后重放恢复；清理浏览器数据会清空它。
- 联机座位凭据保存在当前标签页会话中，刷新或短暂断网会自动重连。对方离线时暂停落子，避免状态分歧。
- 同一个会话在另一个窗口恢复后，旧连接会被移出，不会出现两个窗口同时控制同一座位。
- **房间仅保存在服务进程内存中**。主机重启会清空所有房间；双方离线超过约 30 分钟后房间会被回收。
- 主动点“离开房间”会关闭整个房间；这与临时断线不同。
- 本版面向可信局域网，没有账号、永久战绩或公网运营防护，不建议直接暴露到公网。未部署到 Sites 云端。

## 开发

源码位于 `web/`。使用 Node.js 22.13+（当前验证环境为 24.19）和 pnpm。

```powershell
cd web
pnpm install
pnpm dev
```

生产构建与运行：

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm start
```

`pnpm dev` 和 `pnpm start` 默认均使用 4173 端口，不能同时运行。生产服务可通过环境变量 `PORT` 指定端口。`.env.example` 说明可选配置；社交预览的绝对地址默认为本机地址，若以后部署，构建时应指定可信的 `SITE_ORIGIN`。

### 结构

```text
web/
  app/                 页面与响应式样式
  components/ui/       按钮、输入框和对话框基础组件
  components/energy-token.tsx  棋盘与各处 UI 共用的能量棋子外观
  lib/presentation.ts  基础棋子皮肤与显示名称，不影响规则状态
  lib/game-core.ts     纯规则与状态机；不依赖界面或网络
  lib/use-room.ts      浏览器连接、会话与重连
  server/rooms.mjs     服务端裁定、房间、身份、状态同步
  server/index.mjs     静态网页和 WebSocket 服务
  scripts/build.mjs    静态网页构建
  tests/               规则测试、真实 WebSocket 协议测试
  public/              本地图标与预览封面
```

英雄模式在 `web/lib/match-core.ts` 中独立扩展，使用 `mode` 区分标准与娱乐，底层 `rule: swap2` 仍代表开局和五连规则。没有向 `game-core.ts` 加入英雄特例。棋子历史落点与当前位置独立记录，技能移动后手数标识不会错位，存档可以重放恢复。

### 验证范围

当前规则测试覆盖所有 Swap2 分支、双方四方向五连、长连、边界、非法操作、满盘和棋、认输与纯函数不变性；联机测试使用真实双/多 WebSocket 客户端，覆盖房间人数、回合校验、同步、过期版本、身份恢复和换开局方。

新增测试覆盖技能使用限制、目标验证、原状态不变、换位后五连与长连、天赋四方向与边界、历史棋子身份、存档重放、联机同步与服务端模式隔离。自动化协议测试不等于已在两部手机上实测。不同 Wi-Fi、防火墙、iOS/Android 浏览器仍应由你用实际设备验收。本次没有进行浏览器截图或自动点击测试。

页面提供可选 WebMCP 读局面与执行操作接口，仅在浏览器支持 `document.modelContext` 时注册。普通浏览器不依赖它；本次环境未完成支持 WebMCP 浏览器中的实际调用验证。

网页依照 Sites 的构建规范搭建，针对你要求的局域网场景采用本地 Node 服务，不使用云端持久化。固定版本的 Vinext CLI 在 Windows/Node 24 构建结束时有强制退出错误，因此构建脚本调用同一框架的构建与预渲染 API，正常等待清理完成；编译错误仍会使构建失败。

封面由内置 ImageGen 生成，文件与最终提示词见 [素材记录](web/docs/assets.md)。
